## 2. Architecture

```
dev.html, api-tools.html, workbench.html   ← generated by scripts/gen-pages.mjs from the registry
qr.html                                    ← QR generator (image section)
assets/dev/
  registry.js      single source of truth: every tool {id, cat, group, name, desc, keywords}
  shell.js         page shell: sidebar + search + hash routing (/dev#json-formatter), lazy import of tools, error boundary
  ui.js            shared UI: h(), editor(), output(), msgBox(), seg(), tabs(), kvEditor(), copyText(), download(), toast(), runWorker()
  dev.css          shared components;  css/<group>.css tool-specific styles
  lib/*.js         PURE logic (no DOM) — imported by tools, workers and node unit tests
  tools/<id>.js    one UI module per tool: export function mount(root) → optional cleanup()
  workers/*.js     module workers for heavy / untrusted computations (regex, workbench, diff)
functions/api/     Cloudflare Pages Functions (proxy, webhooks)   — repo-only source, deployed by Pages
server/            shared backend helpers (SSRF guard, rate limit) — imported by functions + unit tests
migrations/        D1 schema (webhooks)
tests/unit         node --test, pure logic
tests/e2e          Playwright (playwright-core + system Chrome) against serve.py (same headers as prod)
```

Principles: browser-side first; libraries lazy-loaded only by the tool that needs them; logic separated
from presentation; user data never inserted as HTML (DOM text nodes only); every tool has real tests.

### Temp Mail (added 2026-11-17)
Self-hosted disposable inbox that receives REAL e-mail + OTP codes. Architecture: Cloudflare Email Routing →
standalone Email Worker (`email-worker/`) parses the raw MIME and writes to D1 → Pages Functions `/api/mail/*`
serve it → `/mail` page polls (7 s) and shows the auto-detected verification code. Pure MIME parser +
OTP extractor in `server/mime.js`; inbox/auth/storage in `server/mail-core.js`. Addresses auto-expire
(1 h idle / 24 h max); inbox readable only with a per-inbox token (SHA-256 stored). Page renders message text
only (HTML converted to text server-side) → no HTML-injection surface. Needs a live domain + Email Routing +
`MAIL_DB`/`MAIL_DOMAIN` bindings to go live (docs/DEPLOYMENT.md); shows "not switched on yet" until then.
Tests: unit/mime (18), unit/mailcore (3), unit/mailworker (3); e2e/mail (8, real delivery via wrangler + D1).
Parser verified against real Groq/Stytch, OpenAI, GitHub, Google, Microsoft, Discord, Amazon formats (7/7).

### Known limitations
- Webhook tester returns “not switched on yet” until the D1 binding `HOOKS_DB` is added in Cloudflare (one-time, ~3 min).
- Proxy rate limit is per Cloudflare isolate (best effort); add a WAF rate-limit rule once on a custom domain.
- GraphQL subscriptions not supported (explained in the UI). Regex = JavaScript flavour. Cron: no Quartz L/W/#.
- JWT: no JWE / encrypted PEM / X.509 certificate input. XML: well-formedness only (no DTD/XSD validation).
- Direct REST requests only see CORS-exposed response headers (browser rule); use “Secure proxy” for all headers.
- QR: in-page check uses jsQR at 3 sizes; very dense content (≈400 chars) can fail at small print size and is warned about.

### Debugging log (root causes fixed)
- `ui.runWorker` referenced `promise` inside its own executor → every worker tool failed; fixed + covered by e2e.
- XML tokenizer computed line numbers per tag (quadratic; 20 k elements = 62 s) → lazy; regression test < 3 s.
- QR library encodes text as Latin-1 → emoji/Hindi/Gujarati corrupted; now UTF-8 bytes; unicode decode test.
- QR tool persisted content (could include Wi-Fi passwords) → now only style is stored; test asserts it.
- ZXing-js gave false “unscannable” results even for perfect reference matrices (v8/v13/v16/v19) → not used;
  zxing-cpp confirmed all 390 preset renders valid; tests use zxing-cpp.
- cron builder kept stale chips; base64 file sniffing; date-range edge in mock data; openapi-viewer syntax error.
